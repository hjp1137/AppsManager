# 本地开发项目管理窗体应用（WPF）设计方案

该方案旨在建立一个基于 **.NET 9.0 WPF** 的现代化本地 Windows 窗体应用，用于高效管理和调试电脑中的多个开发项目，解决多项目开发时端口占用不清、手动启动/关闭繁琐的问题。

## 1. 技术栈选型
*   **开发框架**：.NET 9.0 WPF (Windows Presentation Foundation)
*   **开发语言**：C# 13
*   **UI 风格**：现代暗黑系（Dark Mode），玻璃质感，渐变微动效，状态呼吸灯
*   **持久化**：本地 `projects.json` 配置文件

## 2. 核心功能设计

### A. 项目与子服务管理 (CRUD)
*   **多启动项 (SubService) 支持**：一个“项目”可以包含一个或多个“子服务”启动项（例如：前端、后端、Worker、数据库迁移）。
*   **启动项精细自动识别**：
    *   为了防止探测出过多无法运行的 .NET 类库（Class Library），自动读取 `.csproj` 内容，仅识别 `Sdk` 包含 `Microsoft.NET.Sdk.Web`、`Microsoft.NET.Sdk.Worker`，或者 `OutputType` 为 `Exe` 或 `WinExe` 的可运行项目。
*   **命令行粘贴智能解析器**：
    *   在界面增设“命令解析粘贴框”，允许用户直接粘贴带 `cd` 及 `&&` 的复合命令（例如 `cd web && pnpm dev`），系统自动拆解出运行路径与实际启动指令并生成新启动项。
*   **DataGrid 现代暗黑美化**：
    *   定制 `DataGridColumnHeader` 和 `DataGridRow` 样式，设置纯黑底、高亮前景色，彻底解决暗黑模式下表头泛白、选中项不清晰的硬伤。
*   子服务属性：
    *   `Id` (Guid)

### D. 端口与状态监控 (Status Monitor)
*   定时器轮询检测：每隔 2~3 秒检测已配置端口 of 占用状态。
*   **状态定义**：
    *   🔴 **已停止 (Stopped)**：端口未占用，进程未运行。
    *   🟡 **启动中 (Starting)**：点击了启动，命令已发出，但端口尚未处于监听状态。
    *   🟢 **运行中 (Running)**：端口已被占用，且对应 PID 为我们启动的进程（或已有其他进程占用）。

## 3. UI/UX 界面设计规划

采用现代无边框窗体设计（WindowStyle="None", AllowsTransparency="True"），手绘精美暗色背景。
*   **左侧导航/过滤栏**：项目分组列表，快速切换；一键“停止所有”按钮。
*   **中部主面板**：项目卡片网格列表（Card Grid）。
    *   每个卡片展示项目名、路径、端口、运行状态（带呼吸灯）。
    *   **项目被选中样式**：在卡片实体中加入 `IsSelected` 属性。当卡片被选中时，其外框发出绿色高亮（`#4CAF50`）并且卡片底色微调，确保用户能够一目了然区分正在查看哪个项目的终端日志。
    *   **一键强杀端口冲突 (⚡ 按钮)**：在有端口（`Port > 0`）的子服务行操作栏，新增 ⚡ (闪电) 强杀按钮。当端口被非本应用拉起的残留孤儿进程占用时，点击此按钮可一键定位并强制终止（Kill）冲突的 PID 并释放端口，同时在控制台日志流中实时打印强杀释放的状态回显；而无端口服务（`Port = 0`）则自动隐藏此按钮。
    *   **重启服务 (↻ 按钮)**：在子服务控制行新增 ↻ 重启按钮。点击后在后台异步执行“先停止、等待状态归零释放、再拉起”的流水线逻辑，UI 线程全程无感且绝不卡顿。
    *   **非阻塞异步停止机制**：将所有进程 Kill 和端口释放操作放入后台 Task.Run 线程池异步执行，并重构“一键停止所有”全局命令为完全非阻塞遍历通知，彻底解决同步锁死 WPF 窗口导致程序死掉或崩溃的缺陷。
    *   卡片底部提供：[启动/停止] 按钮、[VS Code] 快捷按钮、[日志] 按钮。
*   **右侧/底部日志终端**：点击子服务日志后展开。
    *   **TabControl 快速切换**：用 TabControl 代替 ComboBox，通过重写 `TabItem` 的 `ControlTemplate` 彻底根除系统默认选中白色背景问题，设置暗色高亮选中前景色。
    *   **状态精确定位与端口自动纠偏**：
        *   优化轮询定时器的端口检测条件，避免 Starting 状态被逻辑卡死。
        *   **日志智能端口纠偏**：在实时日志流处理器中订阅增量日志。为了防止 Vite/Node 等带颜色的控制台输出中夹杂的 ANSI 颜色控制码（如 `\x1b[36m` 等）切割破坏端口文本，匹配前系统将自动先剥离所有 ANSI 颜色代码，然后再通过正则扫描类似 `listening on ...:(\d{4,5})` 或 `localhost:(\d{4,5})` 的字段，智能捕捉子服务实际监听的真实端口。一旦发现与卡片配置端口不一致，系统将自动更正卡片的端口配置并进行持久化保存，从而使后续轮询检测能够 100% 正确击中，瞬间切绿。
    *   **指示灯四色状态化**：页签前方的状态小圆灯升级为四色展示：
        *   🟢 绿色：启动成功（Running）
        *   🟡 黄色：正在启动中（Starting）
        *   🔴 红色：已关闭/启动失败（Stopped 且有日志）
        *   ⚪/⚫ 灰色：待启动（Stopped 且无日志）
    *   **窗体垂直拉伸自适应**：重置右侧主面板的 Grid 布局行权重，主项目卡片列表行高固定为 `320`，日志展示终端行高设为 `*`。主窗体垂直拉高时，多余的高度空间将全部自动扩展给控制台日志 RichTextBox。
    *   **ANSI 颜色解析终端**：将原 `TextBox` 升级为 `RichTextBox`，在后台对输出日志做 ANSI 控制字符（如 `\x1b[32m`）解析，实时进行前景色渲染（如绿色、青色、红色等），彻底洗净 ANSI 乱码并呈现高颜值的控制台日志。

## 5. 关键技术实现方案

### A. 端口占用检测与强杀 (C# 实现)
通过执行 `netstat -ano -p tcp` 并解析输出，获取占用特定端口的 PID。
```csharp
// 强杀占用特定端口的进程
public static void KillProcessOnPort(int port)
{
    var pids = GetPidsByPort(port);
    foreach (var pid in pids)
    {
        try
        {
            var proc = Process.GetProcessById(pid);
            proc.Kill(true); // 递归杀掉子进程
        }
        catch { }
    }
}
```

### B. 进程启动与日志重定向
```csharp
var startInfo = new ProcessStartInfo
{
    FileName = "cmd.exe",
    Arguments = $"/c {item.StartCommand}",
    WorkingDirectory = item.Path,
    RedirectStandardOutput = true,
    RedirectStandardError = true,
    UseShellExecute = false,
    CreateNoWindow = true
};
var process = new Process { StartInfo = startInfo };
process.OutputDataReceived += (s, e) => AppendLog(item.Id, e.Data);
process.ErrorDataReceived += (s, e) => AppendLog(item.Id, e.Data);
process.Start();
process.BeginOutputReadLine();
process.BeginErrorReadLine();
```

## 6. 验证计划

### A. 自动化测试与局部验证
*   使用 C# 控制台或单元测试验证 `PortService` 查找端口 PID 和 `Kill` 的准确度。
*   编写模拟程序占用端口 3000，验证是否能一键检测并释放。

### B. 手动功能验证
*   添加一个测试 Web 项目，配置启动命令为 `npm run dev`（配置端口 5173）。
*   点击“启动调试”，观察是否成功打开网页、是否有日志输出、端口状态是否变成绿色运行中。
*   点击“关闭调试”，验证端口是否被释放，控制台是否彻底停止。
