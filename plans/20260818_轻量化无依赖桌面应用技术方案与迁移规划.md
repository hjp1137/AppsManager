# 轻量化无依赖桌面应用设计与迁移规划方案

## 1. 现状痛点与重构目标

当前 `AppsManager` 基于 **.NET 9.0 WPF** 构建，存在以下局限：
*   **痛点 1：运行时强依赖**：用户机器必须安装 .NET 9 Desktop Runtime；若采用独立打包（Self-contained），单文件体积普遍超过 80MB~120MB。
*   **痛点 2：海量日志轰炸导致 UI 线程卡死**：WPF 的 RichTextBox 在主 UI 线程做文档排版渲染，大量日志快速刷屏时塞爆 Dispatcher 消息队列，导致界面无响应（Not Responding）。
*   **痛点 3：多进程缺乏隔离，单项卡死拖垮全局**：多开应用时，因端口探测阻塞或子进程死锁，公用 Task 线程池与 UI 调度相互竞争，导致整个软件连带卡死。
*   **重构目标**：
    1. **零运行时依赖 (Zero-Dependency)**：目标机器无需安装任何 .NET、Python、Node 等额外软件，单 `.exe` 双击即跑。
    2. **极致轻量**：安装包/单文件大小压缩至 10MB~20MB 以内，闲置内存占用 < 30MB。
    3. **日志高吞吐与硬件加速终端**：采用后端环形缓冲 + 批处理节流 + 前端 xterm.js (Canvas/WebGL)，每秒万行日志依然 60 FPS 丝滑响应。
    4. **完全独立的协程隔离与死锁断路**：各子服务生命周期在独立 Goroutine 隔离运行，单项假死绝不影响其他服务及主界面。
    5. **可靠的底层进程与端口管理**：基于 Windows JobObject 树形管控，秒杀残留孤儿进程与端口冲突。

## 3. 最终推荐架构选型

### 推荐方案：Go (Golang) + Wails v2 / 极简嵌入式 Webview 架构

> **选型理由**：
> 1. **Go 原生静态编译**：直接输出单个原生 `.exe`，无任何外部 DLL 或 Framework 依赖。
> 2. **Win10/Win11 原生友好**：现代 Windows 均自带 WebView2 组件，UI 渲染由系统接管，无需打包大型浏览器内核。
> 3. **极强并发与 I/O 能力**：Go 的 Goroutine + Channel 处理多个子项目并发编译输出日志、端口定时扫描几乎零开销。
> 4. **前端生态复用**：直接使用 HTML5 + TailwindCSS + xterm.js / ansi-to-html，彻底解决 WPF 终端日志卡顿和 ANSI 乱码问题。

## 4. 核心系统模块与架构设计

### 4.1 进程完全隔离与断路管控 (`process_manager.go`)
*   **微内核 Actor 隔离模型**：每个子服务拥有独立的 Goroutine 生命周期与专属 Context，互不共享阻塞通道。
*   **非阻塞与假死断路器 (Deadlock Circuit Breaker)**：
    *   启动命令执行和端口检测均设置独立的超时防护（如 500ms），绝不阻塞主循环和其他子服务。
    *   若某子命令内部假死（如死循环、等待输入、网络卡死），其独立状态机直接标记为 `Deadlocked/Timeout` 并触发报警，主界面和其他服务完全正常运作。
*   **Windows JobObject 树形硬销毁**：通过 `CreateJobObject` 将子进程树严格绑定。点击强杀或停止时，直接调用操作系统级 `TerminateJobObject` 在微秒级连根拔起所有孤儿进程，句柄即刻释放。

### 4.2 海量日志吞吐与背压防护 (`log_streamer.go`)
*   **后端定长环形缓冲 (Ring Buffer)**：每个子服务在 Go 内存中只保留最近 2000~5000 行日志，超出自动滚动淘汰，彻底防止内存无限制暴涨。
*   **微批处理与节流推送 (Batch Throttle)**：
    *   对 `stdout/stderr` 管道采用带缓冲的读取（`bufio.Reader`）。
    *   采用 **50ms 聚合窗口**：在 50ms 内到达的多行日志打包成单一数据包一次性推向前端，从源头避免 IPC 消息总线风暴。

### 4.3 端口监控与毫秒级强杀 (`port_manager.go`)
*   **非阻塞快速端口检测**：采用 Go 标准库 `net.DialTimeout(100ms)` 或调用 Windows `GetExtendedTcpTable` API 极速探测，无须启动任何子 shell 管道。
*   **一键强杀冲突 PID**：毫秒级定位占用 PID，直接调用 `taskkill /F /T /PID` 或 Win32 `OpenProcess` + `TerminateProcess`。

### 4.4 现代化前端 UI 与硬件加速终端 (`frontend/`)
*   **技术栈**：Vue 3 + Tailwind CSS + Lucide Icons + `xterm.js`（VS Code 底层同款终端）。
*   **极致渲染性能**：
    *   使用 Canvas / WebGL 硬件加速绘制日志，完全绕过浏览器 DOM 树重排计算。
    *   即便每秒输出上万行日志，UI 帧率依然稳固在 60 FPS，彻底根除 WPF RichTextBox 界面卡死硬伤。
    *   天然原生支持 ANSI 256 色及 RGB 真彩色解析与超链接点击。
    *   多项目卡片网格、呼吸灯状态指示、一键重启/强杀/打开目录。

## 5. 迁移与分阶段落地路线

```
[Phase 1: Go 核心引擎开发] 
  ├── 进程管理 (JobObject + stdout/stderr 流)
  ├── 端口检测与 PID 强杀 (Win32/net)
  └── JSON 配置与项目扫描器兼容
        │
        ▼
[Phase 2: 现代前端界面搭建]
  ├── Vue 3 + Tailwind 暗色卡片列表
  ├── 呼吸灯状态与实时 WebSocket/Wails Event 绑定
  └── ANSI 彩色日志终端组件集成
        │
        ▼
[Phase 3: 联调、打包与交付]
  ├── Wails / 嵌入式 Webview 编译单文件 (.exe < 15MB)
  ├── Windows 任务栏托盘集成 (SysTray)
  └── 零环境依赖安装与启动自测
```

## 6. 验证与验收指标

1. **环境纯净性验证**：在未安装 .NET SDK/Runtime、未安装 Node、未安装 Python 的纯净 Windows 10/11 虚拟机中，双击 `.exe` 能正常秒开界面。
2. **打包体积与内存验证**：Release 产物 `.exe` 体积控制在 20MB 以内，闲置运行内存控制在 30MB 左右。
3. **功能闭环测试**：
   * 启动包含 Vite/Node、Go、Python、.NET 的测试项目，验证日志实时染色、ANSI 字符清洗、端口纠偏、进程停止无残留孤儿。
   * 模拟 3000/5173 端口冲突，测试一键强杀（⚡）及端口释放响应。
