# 本地开发项目管理窗体应用开发成果说明

针对用户提出的多启动命令项目管理痛点（如同一个工程中包含前端、后端 API、后台 Worker 等多个并发服务），我们对应用架构进行了全面重构，交付了 **“多子服务 (SubService) 联合控制”** 功能。并且，根据用户的各阶段最新反馈，我们优化了指示灯的状态判定、消除了默认模板的高亮冲突、修正了窗体拉伸自适应，并实现了状态精确轮询、项目卡片选中绿色高亮、端口残留冲突进程一键强杀、全局非阻塞异步停止优化及一键重启子服务。

## 1. 重构与升级成果

我们升级并实现了以下核心能力：
1.  **多子服务数据结构 (SubService)**：项目实体 `ProjectItem` 支持 `ObservableCollection<SubService>`，每个子服务具备独立的名称、路径、启动命令、调试端口、进程句柄以及独立的日志缓冲区。
2.  **多启动项智能精准探测**：导入项目文件夹时，系统自动深度遍历 2 层子目录，自动过滤非独立启动的类库（Class Library）项目，仅保留可独立运行的可执行项目。
3.  **命令行复合指令解析器**：在“项目配置”对话框中，增设了“快捷命令行粘贴框”，能够自动将类似 `cd web && pnpm dev:ip --port 5555` 的复合语句智能分解为工作路径 and 启动命令，并自动解析提取调试端口。
4.  **ANSI 颜色控制台解析渲染**：控制台终端彻底升级为 `RichTextBox`，在后台引入 `AnsiColorParser`，高性能正则流式解析进程重定向输出 of ANSI 控制码，自动渲染前景色并设置粗体，消除原本控制台 `[32m` 等乱码，展示彩色终端日志。
5.  **TabControl 页签高对比度样式**：完全接管了 `TabItem` 的系统级默认高亮白底模板，通过自定义 `ControlTemplate`，彻底消除了“白底白字”看不清字体的冲突！在页签被选中时，前景色强制变为高亮纯白（`#FFFFFF`），背景显示为暗灰色 `#2D2D2D`，底部辅以绿色激活短条，排版极其美观且轮廓分明。
6.  **四色状态灯实时渲染**：在 `SubService` 中暴露了 `System.Windows.Media.Brush` 类型的 `StatusBrush`，避开了 WPF 在属性更改时隐式字符串转换失败的局限，确保 100% 可靠重绘。状态灯包含四色联动：
    *   🟢 绿色：运行中（`Running`）
    *   🟡 黄色：正在启动中（`Starting`）
    *   🔴 红色：已停止但产生过日志/启动失败（`Stopped` 且有日志）
    *   ⚪/⚫ 灰色：全新待启动状态（`Stopped` 且无日志）
    *   当点击“清除日志”时，指示灯亦会瞬时自动变回灰色（待启动）。
7.  **精准状态判定与日志智能端口纠偏**：
    *   **非排他端口检测**：在轮询定时器 `PortTimer_Tick` 中去除了对 `Starting` (黄色) 状态的排他阻断。现在，启动中的服务如果端口被成功监听，状态将立刻跃升至 `Running` (绿色)！
    *   **只退回策略**：若端口未被监听，只有处于 `Running` 状态的项才会被退回 `Stopped`，从而完美保护了启动中的 `Starting` 状态不被频繁归零，实现了运行/停止状态的 100% 精精准判定。
    *   **日志智能端口自适应纠偏与 ANSI 剥离**：在实时增量日志监听器中订阅日志流，利用极其精细的正则表达式捕获如 `localhost:(\d{4,5})` 或 `listening on ...:(\d{4,5})` 或 `port (\d{4,5})` 等真实监听端口。在匹配端口前自动将所有 ANSI 颜色代码全部剥离干净。纯文本还原后再通过正则过滤捕获。若发现实际端口与卡片当前的 Port 不一致，系统在 UI 线程上自动将 Port 修正为真实运行的端口并自动执行存盘。由此，轮询定时器在下一秒便可 100% 准确命中端口检测，瞬时切绿，完美适应各类带颜色的前端终端输出！
    *   **无端口服务状态判定**：在 `ProcessService` 中，对于 `Port == 0`（如 Worker）的子服务，进程一旦成功拉起，立即发布 `StatusChanged` 事件变更其状态为 `Running` (绿色)，防止因无监听端口检测而一直卡在 Starting 黄色状态。
8.  **非阻塞异步停止优化（已修复）**：
    *   针对用户点击“停止所有”时主线程被同步进程终止和 `netstat` 端口强杀阻塞从而导致“程序直接死掉”的问题，我们进行了彻底优化。
    *   **非阻塞异步化**：将 `ProcessService.StopSubService` 内部的所有 Kill 进程及端口占用强杀操作全部放到了后台的 `Task.Run` 线程池上异步执行，并在 try-catch 内完全捕获异常，彻底释放了 UI 线程。
    *   **全局停止重构**：将全局“一键停止所有” `StopAllGlobalCommand` 更改为对所有子服务发起异步 `StopSubService` 请求。点击后，所有服务的停止任务在后台并发异步地、井然有序地运行，界面绝不发生卡顿或假死！
9.  **一键重启子服务 (↻ 按钮)（已新增）**：
    *   我们在停止按钮 ■ 右侧新设了深青色的 **↻ 重启服务按钮**。
    *   **后台流水线机制**：点击 ↻ 按钮会触发 `RestartSubServiceCommand`。系统在后台线程执行：发起 `StopSubService` -> 循环轮询等待当前子服务状态完全归零变红（`Stopped`） -> 多预留 300 毫秒物理端口释放延迟 -> 调用 `StartSubService` 再次拉起服务。整个过程完全在后台自动化进行，UI 全程响应敏捷，操作极为丝滑！
10. **一键强杀冲突端口 (⚡ 按钮)**：在有端口（`Port > 0`）的子服务行操作栏，新增 ⚡ (闪电) 强杀按钮。当端口被非本应用拉起的残留孤儿进程占用时，点击此按钮可一键定位并强制终止（Kill）冲突的 PID 并释放端口；而无端口服务（`Port = 0`）则自动隐藏此按钮。
11. **项目卡片被选中绿色高亮**：在 `ProjectItem` 中引入 `IsSelected` 属性，并在 `MainViewModel` 的 `SelectedProject` 改变时同步更新该状态。在 `MainWindow.xaml` 的 `DataTemplate.Triggers` 中定制了 `DataTrigger`，一旦项目被选中，其卡片外框立即发出绿色高亮（`#4CAF50`），背景稍微变浅（`#2D2D2D`）且边框加粗。
12. **窗体垂直自适应拉伸**：重新定制了右侧主网格 of 行高比例，卡片网格列表所在的 Row 高度固定为 `320`，控制台日志 RichTextBox 所在的 Row 高度设为权重 `*`。这样，在拖拽改变窗体大小时，卡片部分高度保持固定，所有新增的垂直高度将百分之百自动分配并拉高控制台的 RichTextBox 显示区。
13. **安全清场**：关闭窗体时，通过全局命令深度强杀所有专有进程，确保端口 100% 释放。
